A proposal to turn the hub from a set of generated pages into an app the team opens every morning. It covers who uses it and for what, a new structure, wireframes, a visual system, and two phases: first a new front-end on today's data, then sign-in and write actions.

5. Visual system

Keep the Beyond One look (Poppins, ink, the red mark). What changes is what each colour means, so that every colour on screen carries one meaning only.

Ink: text, the active phase, primary buttons
Brand red: logo and the active nav item only
Critical, blocked, failed
High
Medium
Low
Passed, approved
Running, in progress
  • Status is a dot plus a word, never colour alone and never emoji. This meets WCAG 1.4.1 and reads the same on every OS.
  • Type: Poppins for the interface; JetBrains Mono only for things you copy and run (commands, branch names, keys). Numbers use tabular figures so the columns line up.
  • Density: a compact mode for tables (Quality, Tasks) and a comfortable mode for reading (Knowledge). Light and dark themes are both kept.
  • Quality floor (from the installed baseline-ui and fixing-accessibility skills): accessible primitives for menus, tabs and dialogs; visible keyboard focus; prefers-reduced-motion respected; no animation except feedback on an action; usable on a phone at 360px.

6. Phase 1: new front-end on today's data

The cut is the data contract. Everything that produces content/ stays as it is: spec.py json, sync_loop.py, sync_engineering_hub.py, the test-execution recorder, build.mjs's manifest and publish.py's stripping. Only what reads content/ is replaced.
ConcernChoiceWhy
FrameworkReact 19 + TypeScript, built with ViteThe 1,933-line hub.js builds pages from HTML strings. Typed components for each tab, card and table can be tested and reused across hubs.
RoutingReact Router, hash modeStatic hosting keeps working without server rewrites, and the old #/ links redirect in one table.
StylingTailwind CSS v4, with brand tokens read from brand.json at build timeOne token set per hub. Rebranding still needs no engine edit.
PrimitivesBase UI (tabs, menu, dialog, popover, combobox)Keyboard and focus handled for us (baseline-ui rule)
DataTyped loaders for loop.json, specs/*/findings.json, test-executions/*.json and the manifest; the live panel polls every 2 s as todayNo change to the generators
Markdown and diagramsmarked and mermaid, as today, bundled instead of loaded from a CDNSame rendering. The hub works offline on a laptop.
SearchMiniSearch index generated by build.mjs⌘K over work, findings, documents and commands
AccessSoft passcode gate keptReal sign-in is phase 2
Engine deliveryengine-files.txt lists dist/ instead of index.html and assets/js/*. hub-update.sh copies a built engine. Hubs need Node only to build.Each hub keeps only its content/ and images, as today
DeployUnchanged: node build, then nginx-unprivileged on 8080 with /healthz on dev-shrd-eu-rke2No platform change, no BeyondBase re-onboarding
Carried-over risk. The Beyond One hub's notes say deploy/publish.py does not yet strip security findings from content/specs/*/findings.json. The new Quality section reads those files, so it would show them. Fix the strip before the first publish of v5.

7. Phase 2: sign-in and actions

The goal: the team can act from the hub (approve a gate, move a task, comment), and the hub stays a view of git. It never becomes a second source of truth.

CapabilityHow
Sign-inOIDC in front of the app. Beyond One SSO or Keycloak (already in the stack): to decide.
RolesViewer, engineer, tech lead, owner. Security findings are visible only to engineers and up, enforced by the API, not by the publish step.
Approve a gateThe API runs the equivalent of spec.py approve <KEY> <phase> --by "<signed-in name>" as a commit in engineering-workspace, through a GitHub App. P-1 (nothing is built that is not in an approved spec) stays auditable in git history.
Move a taskThe same route as spec.py task <KEY> <id> <status>
CommentsThe existing backend/comments API (Lambda + DynamoDB), signed in, attached to work item, tab and finding
FreshnessA workspace push triggers a sync job that regenerates content/. The hub shows "updated n min ago".
ServiceA small Node API (Fastify) as a second container in the same chart, on the BeyondBase platform

Phase 2 gets its own design version once phase 1 is in use. The open choices are listed in section 9.
